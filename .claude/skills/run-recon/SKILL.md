# Skill: run-recon

## Description
Generates a standalone reconciliation module that compares source data against
the target Iceberg table. Supports multiple rule types and returns a structured
report with per-rule results and an overall status.

## Prerequisites
This skill assumes the pipeline has been generated (via `/generate-pipeline`)
and the target Iceberg table exists. The reconciliation module is designed to
run within the same compute context as the pipeline (Spark for Glue/EMR,
boto3 Lambda invocation for Lambda/ECS).

## Inputs
- Pipeline config YAML path via `$ARGUMENTS`
- If no path provided, scan the `configs/` directory for `.yaml` files

## Templates
Read these templates if available for boilerplate patterns. Generate code directly
from config values regardless of whether templates exist.

- `templates/common/reconciliation.py` -- shared reconciliation logic

## Output
- Reconciliation module at `pipelines/{product.name}/recon/{product.name}_recon.py`

## Generation Steps

### Step 1: Read Config and Extract Reconciliation Rules

1. Read the pipeline config YAML from `$ARGUMENTS` or `configs/` directory.
2. Extract `product.name`, `product.domain`, `compute.engine`.
3. Extract `reconciliation.rules` array. If empty or absent, generate a
   skeleton module with a warning log and return an empty PASS report.
4. Extract `target.catalog`, `target.database`, `target.table` for target
   queries.
5. Extract `sources[N].connection.*` for Snowflake source queries (connection
   is nested inside each source entry, not at the top level).

### Step 2: Determine Execution Context

Based on `compute.engine`, determine how the reconciliation module will execute:

- **Glue / EMR** (PySpark engines): Generate a `run_reconciliation()` function
  that accepts a `SparkSession`. Source queries execute via the Snowflake Spark
  connector (`spark.read.format("net.snowflake.spark.snowflake")`). Target
  queries execute via `spark.sql()` against the Iceberg catalog.

- **Lambda / ECS** (Python+Pandas engines): Generate a Lambda-invocable
  reconciliation handler. Source queries execute via
  `snowflake-connector-python` (DBAPI cursor). Target queries execute via
  `pyiceberg` catalog. Alternatively, generate a boto3 invocation stub that
  calls a dedicated reconciliation Lambda.

### Step 3: Generate Reconciliation Module (PySpark Engines)

For Glue/EMR, generate a module with the following structure:

#### Module Docstring
```python
"""
Reconciliation module for {product.name}
Product: {product.name} | Domain: {product.domain}
Generated by AI SDLC Pipeline Generator
Engine: {compute.engine} (PySpark)
"""
```

#### Imports
```python
import logging
import uuid
import json
from datetime import datetime
import boto3
```

#### Initialization

Before the rule loop, initialize the accumulator variables:
```python
overall_status = "PASS"
results = []
```

#### Function Signature
```python
def run_reconciliation(spark, sf_options, target_table, logger, correlation_id=None):
    """
    Runs reconciliation checks comparing source data against target Iceberg table.

    Args:
        spark: Active SparkSession with Iceberg catalog configured
        sf_options: dict of Snowflake connection options for source queries
        target_table: Fully-qualified Iceberg table identifier
            (e.g., "glue_catalog.db_name.table_name")
        logger: Logger instance with correlation ID
        correlation_id: Optional correlation ID for tracing

    Returns:
        dict with overall_status, run_timestamp, correlation_id, and per-rule results
    """
```

#### Rule Processing

For each rule in `reconciliation.rules`, generate a check block based on `type`:

**`row_count`**:
```python
source_val = (
    spark.read.format("net.snowflake.spark.snowflake")
    .options(**{**sf_options, "query": rule["source_expr"]})
    .load().collect()[0][0]
)
target_val = spark.sql(rule["target_expr"]).collect()[0][0]
diff_pct = abs(source_val - target_val) / max(source_val, 1) * 100
passed = diff_pct <= rule["tolerance_pct"]
```

**`sum`**:
```python
source_val = (
    spark.read.format("net.snowflake.spark.snowflake")
    .options(**{**sf_options, "query": rule["source_expr"]})
    .load().collect()[0][0]
)
target_val = spark.sql(rule["target_expr"]).collect()[0][0]
diff_pct = abs(source_val - target_val) / max(abs(source_val), 1) * 100
passed = diff_pct <= rule["tolerance_pct"]
```

**`distinct_count`**:
```python
source_val = (
    spark.read.format("net.snowflake.spark.snowflake")
    .options(**{**sf_options, "query": rule["source_expr"]})
    .load().collect()[0][0]
)
target_val = spark.sql(rule["target_expr"]).collect()[0][0]
diff_pct = abs(source_val - target_val) / max(source_val, 1) * 100
passed = diff_pct <= rule["tolerance_pct"]
```

**`null_check`**:
```python
# null_check has no source_expr (or source_expr is "N/A")
null_count = spark.sql(rule["target_expr"]).collect()[0][0]
passed = null_count == 0
```
- Do NOT execute `source_expr` for null_check rules.
- Any non-zero null count is a failure.

**Unknown rule type**:
- Log a warning and mark the rule as `SKIP` with a message.
- Do not fail the overall status for unknown types.

#### Result Structure

Each rule produces a result dict. After building the result, check `passed`
and update `overall_status`:
```python
# For row_count, distinct_count:
result = {
    "rule": rule["name"],
    "type": rule["type"],
    "source_value": source_val,
    "target_value": target_val,
    "diff_pct": round(diff_pct, 4),
    "tolerance_pct": rule["tolerance_pct"],
    "status": "PASS" if passed else "FAIL",
}

# For sum (cast to float to avoid Decimal serialization issues):
result = {
    "rule": rule["name"],
    "type": rule["type"],
    "source_value": float(source_val),
    "target_value": float(target_val),
    "diff_pct": round(diff_pct, 4),
    "tolerance_pct": rule["tolerance_pct"],
    "status": "PASS" if passed else "FAIL",
}

# For null_check:
result = {
    "rule": rule["name"],
    "type": rule["type"],
    "null_count": null_count,
    "status": "PASS" if passed else "FAIL",
}

# After building the result dict for any rule type:
if not passed:
    overall_status = "FAIL"
results.append(result)
logger.info(f"Rule {rule['name']}: {result['status']}")
```

#### Error Handling Per Rule

Wrap each rule check in its own try/except:
```python
try:
    # ... rule check ...
except Exception as e:
    logger.error(f"Rule {rule_name} failed with error: {str(e)}", exc_info=True)
    results.append({
        "rule": rule_name,
        "type": rule_type,
        "status": "ERROR",
        "message": "Rule evaluation failed. See pipeline logs for details.",
    })
    overall_status = "FAIL"
```
Do NOT include `str(e)` in the result dict `message` field -- raw exception
messages may expose internal infrastructure details (table names, ARNs, SQL).
Log the full error with `exc_info=True` for debugging, but return only a
sanitized message in the structured report.

A single rule error must not prevent other rules from executing.

#### Return Value

```python
return {
    "overall_status": overall_status,  # "PASS" or "FAIL"
    "run_timestamp": str(datetime.utcnow()),
    "correlation_id": correlation_id or str(uuid.uuid4()),
    "rules": results,  # list of per-rule result dicts
}
```

### Step 4: Generate Reconciliation Module (Python+Pandas Engines)

For Lambda, generate a Lambda handler. For ECS, generate a `main()` entry point
with `argparse` and `sys.exit()` (matching the ECS entrypoint pattern from
`/generate-ecs-pipeline`). The reconciliation logic is the same for both.

#### Function Signature (Lambda)
```python
def handler(event, context):
    """
    Reconciliation Lambda handler.

    Args:
        event: dict with correlation_id
        context: Lambda context object

    Returns:
        dict with overall_status, run_timestamp, correlation_id, and per-rule results
    """
```

For ECS, use `def main():` with `argparse` and `sys.exit(0/1)` instead.

#### Credential Retrieval

Retrieve Snowflake OAuth token from Secrets Manager before the rule loop:
```python
sm_client = boto3.client("secretsmanager")
secret = sm_client.get_secret_value(
    SecretId=f"adp/snowflake/{connection_account}/oauth"
)
oauth_token = json.loads(secret["SecretString"])["access_token"]
```

Build `conn_params` from the connection config (same pattern as
`/generate-lambda-pipeline` Sub-step 6c). Do NOT accept credentials via the
`event` payload or environment variables.

#### Source Queries (Snowflake DBAPI)

Use context managers for safe connection cleanup:
```python
with snowflake.connector.connect(**conn_params) as conn:
    with conn.cursor() as cursor:
        cursor.execute(rule["source_expr"])
        source_val = cursor.fetchone()[0]
```

#### Target Queries (PyIceberg)

Read the AWS region from `os.environ["AWS_REGION"]` (Lambda) or
`os.environ.get("AWS_DEFAULT_REGION", os.environ.get("AWS_REGION"))` (ECS).
Use `{target.catalog}` from the config -- do NOT hardcode `"glue_catalog"`:

```python
aws_region = os.environ["AWS_REGION"]
catalog = load_catalog(
    "{target.catalog}",  # from config
    **{"type": "glue", "client.region": aws_region}
)
table = catalog.load_table(f"{target_database}.{target_table_name}")
df = table.scan().to_pandas()

# row_count:
target_val = len(df)

# sum (extract column from target_expr, e.g., "total_revenue"):
target_val = float(df[column_name].sum())

# distinct_count:
target_val = df[column_name].nunique()

# null_check:
null_count = df[column_name].isna().sum()
```

Note: `table.scan().to_pandas()` loads the entire table into memory. For large
tables, consider using `table.scan(row_filter=...)` to push down predicates.

#### Comparison Logic
Same tolerance and diff_pct calculations as the PySpark version.

### Step 5: Division-by-Zero Guards

For all comparison rules (`row_count`, `sum`, `distinct_count`):
- Use `max(source_val, 1)` for `row_count` and `distinct_count` to guard
  against division by zero when source value is 0.
- Use `max(abs(source_val), 1)` for `sum` to handle negative sums correctly.

### Step 6: Validation

After generating the reconciliation module, verify:
- All rule types from the config are handled (`row_count`, `sum`,
  `distinct_count`, `null_check`).
- `null_check` rules do NOT execute `source_expr`.
- Each rule is wrapped in its own try/except.
- The return structure includes `overall_status`, `run_timestamp`,
  `correlation_id`, and `rules` array.
- Division-by-zero is guarded in all percentage calculations.
- Source queries for PySpark use the Snowflake Spark connector (not
  `spark.sql()`) since source data is in Snowflake, not in the catalog.
- Logger messages include the rule name and status.
- Unknown rule types are handled gracefully (SKIP, not ERROR).

## Cross-Cutting Concerns

1. **Structured logging**: Log each rule name, type, and result status.
   Include correlation ID in all log messages.

2. **Error isolation**: Each rule runs independently. One rule's failure or
   error must not prevent subsequent rules from executing.

3. **Source query pattern**: For PySpark engines, source queries MUST use the
   Snowflake Spark connector (`spark.read.format("net.snowflake.spark.snowflake")`)
   since source data resides in Snowflake, not in the Iceberg catalog.
   Do NOT use `spark.sql()` for source expressions.

4. **Tolerance semantics**: `tolerance_pct` is a percentage threshold.
   `diff_pct <= tolerance_pct` means the check passes.

5. **Module-level error handling**: An unhandled exception inside
   `run_reconciliation()` must propagate to the caller (re-raise). The
   per-rule try/except isolates individual rule failures; it does not
   suppress failures in the overall function setup (e.g., SparkSession
   unavailable, missing config keys).

6. **Division-by-zero distinction**: The `sum` guard uses
   `max(abs(source_val), 1)` (not `max(source_val, 1)`) because sums
   can be negative. Do NOT "normalize" this to match the simpler guard
   used for `row_count`/`distinct_count`.

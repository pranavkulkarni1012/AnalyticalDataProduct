# Skill: generate-lambda-pipeline

## Description
Generates a Python+Pandas Lambda function for lightweight ETL jobs. This skill is
invoked by `/generate-pipeline` when `compute.engine` is `lambda`.

Uses `snowflake-connector-python` (DBAPI) for Snowflake reads and `pyiceberg` for
Iceberg writes. All transformations use pandas DataFrames -- no Spark dependency.

## Prerequisites
This skill assumes `/validate-config` and `/validate-connection` have already run and
passed (normally invoked by `/generate-pipeline` before delegation). If invoked directly,
run both validators first.

## Key Differences from PySpark (Glue/EMR)
- No Spark -- uses **pandas DataFrames** for all transformations.
- Snowflake reads via `snowflake-connector-python` (DBAPI cursor, not Spark connector).
- Iceberg writes via `pyiceberg` library (not Spark `writeTo`).
- Lambda handler signature: `handler(event, context)`.
- 15-minute timeout and 10 GB memory limit -- validate dataset size.
- No SparkSession, no GlueContext, no PySpark functions.

## Inputs
- Pipeline config YAML path via `$ARGUMENTS`
- If no path provided, scan the `configs/` directory for `.yaml` files

## Templates
Read these templates if available for boilerplate patterns. Generate code directly from
config values regardless of whether templates exist.

- `templates/python/lambda_handler.py` -- Lambda-specific boilerplate
- `templates/python/snowflake_reader_pandas.py` -- shared with ECS
- `templates/python/iceberg_writer_pyiceberg.py` -- shared with ECS
- `templates/common/reconciliation.py` -- shared reconciliation logic

## Output
- Generated Lambda handler at `pipelines/{product.name}/lambda_jobs/{product.name}_handler.py`
- Generated requirements.txt at `pipelines/{product.name}/lambda_jobs/requirements.txt`

## Code Generation Steps

### Sub-step 1: Module Docstring

Include:
- Job name: `adp-{product.domain}-{product.name}-etl-prod`
- Product name, domain, version
- "Generated by AI SDLC Pipeline Generator"
- Note: "Lambda (Python+Pandas) -- no Spark dependency"

### Sub-step 2: Imports

```python
import os, logging, uuid, json
from datetime import datetime
import boto3
import snowflake.connector
import pandas as pd
from pyiceberg.catalog import load_catalog
import pyarrow as pa
```

Do NOT import any PySpark or awsglue modules. Do NOT import `from pyiceberg.table
import Table` -- the table object is obtained via `catalog.load_table()` directly.

### Sub-step 3: Structured Logging Setup

Create a logger named `{product.name}_etl` with a correlation ID (`uuid.uuid4()`).
Use a `logging.LoggerAdapter` to inject the correlation ID into every log message:

```python
product_name = "{product.name}"  # baked in from config at generation time
correlation_id = str(uuid.uuid4())

base_logger = logging.getLogger(f"{product_name}_etl")
base_logger.setLevel(logging.INFO)
handler_log = logging.StreamHandler()
handler_log.setFormatter(
    logging.Formatter("%(asctime)s | %(levelname)s | %(correlation_id)s | %(message)s")
)
base_logger.addHandler(handler_log)
logger = logging.LoggerAdapter(base_logger, {"correlation_id": correlation_id})
```

Define the logging setup inside the `handler()` function so each invocation gets
a fresh correlation ID. The `product_name` variable is also used later in
reconciliation invocation -- define it at the top of `handler()`.

### Sub-step 4: Dataset Size Validation

At the start of `handler()`, validate that the expected dataset size is appropriate
for Lambda:
- If config metadata includes estimated row counts or data size, check that the
  total is under 500 MB (recommended limit for Lambda memory).
- Log a warning if the dataset may exceed Lambda's memory capacity.
- This is an advisory check -- do not block execution.

### Sub-step 5: Lambda Handler Function

Generate the handler with the standard Lambda signature:

```python
def handler(event, context):
    correlation_id = str(uuid.uuid4())
    # ... logging setup ...
    logger.info(f"Starting Lambda ETL job")
    logger.info(f"Correlation ID: {correlation_id}")

    env = event.get("env", os.environ.get("ENV", "prod"))

    try:
        # ... data processing (sub-steps 6-11) ...

        logger.info("Job completed successfully.")
        return {
            "statusCode": 200,
            "body": json.dumps({
                "status": "SUCCESS",
                "correlation_id": correlation_id
            })
        }
    except Exception as e:
        logger.error(f"Job failed: {str(e)}", exc_info=True)
        return {
            "statusCode": 500,
            "body": json.dumps({
                "status": "FAILED",
                "error": "ETL job failed. Check CloudWatch logs for details.",
                "correlation_id": correlation_id
            })
        }
```

Key Lambda-specific patterns:
- Return structured JSON response (not raise on failure for non-async invocations).
- Read `env` from event payload or environment variables.
- Each invocation gets a fresh `correlation_id`.

### Sub-step 6: Snowflake Source Reading

**For each source in `sources`**, perform steps a through f. Note: `connection`
is nested inside each source entry (`sources[N].connection.*`), not at the
top level of the config.

a. Set proxy environment variables from `sources[N].connection.proxy` (both
   lowercase and uppercase variants: `http_proxy`, `https_proxy`, `HTTP_PROXY`,
   `HTTPS_PROXY`). If all sources share the same proxy, set once before the loop.
   If `sources[N].connection.proxy` is absent, skip proxy setup.
   Note: If the proxy URL contains credentials, retrieve them from Secrets
   Manager rather than embedding them in the config.

b. Retrieve OAuth token from AWS Secrets Manager:
   - Secret path: `adp/snowflake/{sources[N].connection.account}/oauth`
   - `sources[N].connection.account` is the full account locator including the
     region (e.g., `company-prod.us-east-1`), so the path resolves to
     `adp/snowflake/company-prod.us-east-1/oauth`.
   - Extract `access_token` from the JSON secret value.
   - Wrap the Secrets Manager call in its own try/except for clear error messaging.
   - If all sources share the same account, retrieve the token once before the loop.

c. Build Snowflake connection parameters per source:
   ```python
   conn_params = {
       "account": sources[N].connection.account,
       "authenticator": "oauth",
       "token": oauth_token,
       "warehouse": sources[N].connection.warehouse,
       "role": sources[N].connection.role,
       "database": sources[N].database,
       "schema": sources[N].schema,
       "proxy_host": "{proxy_host}",  # if proxy configured
       "proxy_port": {proxy_port},     # if proxy configured
   }
   ```
   Note: `use_proxy` is a Spark connector key -- do NOT add it to `conn_params`.
   The DBAPI connector uses only `proxy_host` and `proxy_port`.

d. Build a SQL query using fully-qualified `database.schema.table` names. Quote
   all identifiers with double-quotes to prevent SQL injection:
   ```python
   def quote_identifier(name: str) -> str:
       return '"' + name.replace('"', '""') + '"'
   ```
   - If `columns` is `"*"`, select all columns.
   - If `columns` is an array, select the listed columns (quoted).
   - If `filters` is a non-empty array, add a `WHERE` clause joining filters
     with `AND`. These filters use Snowflake SQL syntax (e.g., `DATEADD(...)`)
     and are pushed down to Snowflake -- do NOT reuse them as pandas filters.

e. Read into a pandas DataFrame using context managers for safe connection cleanup:
   ```python
   with snowflake.connector.connect(**conn_params) as conn:
       with conn.cursor() as cursor:
           cursor.execute(query)
           df = cursor.fetch_pandas_all()
   ```
   Use `cursor.fetch_pandas_all()` for result sets. Use `cursor.fetchone()[0]`
   for scalar results (e.g., COUNT queries in dataset size validation).

f. Log the source name and row count (`len(df)`).

### Sub-step 7: Generate Joins

From `transformations.joins`:
- If empty or absent, skip. Use the sole source DataFrame for sub-step 8.
  If multiple sources but no joins, use the first source and log a warning.
- For each join, use `pandas.merge()`:
  ```python
  df_joined = pd.merge(
      df_left, df_right,
      left_on="left_key", right_on="right_key",
      how="inner"  # or left, right, outer
  )
  ```
  Note: pandas uses `"outer"` instead of `"full"`. Map `full` -> `outer`.
- Drop duplicate join key columns if `left_key != right_key`.
- Log each join operation.

### Sub-step 8: Apply Column Mappings and Generate Aggregations

First, apply `transformations.column_mappings` that create derived columns.
For each mapping, translate the SQL expression to direct pandas operations
(do NOT use `pd.eval()` for SQL-style expressions -- it does not support
`pd.to_datetime()`, `.dt` accessor, or SQL functions). For example:
- `DATE_TRUNC('month', column)` translates to:
  ```python
  df["revenue_month"] = pd.to_datetime(df["order_date"]).dt.to_period("M").dt.to_timestamp()
  ```
- Simple arithmetic expressions can use `df.eval("col_a * 1.1")` (called on
  the DataFrame instance, not `pd.eval()`).

Note on source-qualified column names: After `pd.merge()`, columns from
different sources are available by their unqualified names (e.g.,
`product_catalog.category` becomes `category`). If a name collision occurs,
pandas adds `_x`/`_y` suffixes -- resolve these explicitly. When
`column_mappings` or `aggregations.group_by` reference qualified names like
`{source_name}.{column}`, substitute the post-merge unqualified name.

When a `group_by` entry is a SQL expression (e.g., `DATE_TRUNC('month', ...)`),
replace it with the corresponding `column_mappings.target` alias before
constructing the `groupby()` call.

Then, generate aggregations:
- Use `pandas.groupby().agg()`:
  ```python
  df_agg = df.groupby(["product_category", "revenue_month"]).agg(
      total_revenue=("total_amount", "sum"),
      order_count=("order_id", "nunique"),  # count_distinct -> nunique
      avg_order_value=("total_amount", "mean"),  # avg -> mean
      total_units_sold=("quantity", "sum"),
  ).reset_index()
  ```
- Map aggregate function names:
  - `sum` -> `"sum"`
  - `count` -> `"count"`
  - `count_distinct` -> `"nunique"`
  - `avg` -> `"mean"`
  - `min` -> `"min"`
  - `max` -> `"max"`

### Sub-step 9: Apply Post-Aggregation Filters

From `transformations.filters`:
- These are simple expressions (e.g., `"total_revenue > 0"`).
- Apply using `df = df.query("total_revenue > 0")` or `df = df[df["total_revenue"] > 0]`.
- Do NOT re-apply `sources[].filters` here.

### Sub-step 10: Write to Iceberg Target

Use the `pyiceberg` library to write to the Iceberg table. Read the AWS region
from the Lambda environment variable `os.environ["AWS_REGION"]` (automatically
set by the Lambda runtime):

```python
aws_region = os.environ["AWS_REGION"]

catalog = load_catalog(
    "{target.catalog}",  # from config, e.g., "glue_catalog"
    **{
        "type": "glue",
        "client.region": aws_region,
    }
)
table = catalog.load_table(f"{target.database}.{target.table}")

arrow_table = pa.Table.from_pandas(df_result)

if write_mode == "overwrite":
    table.overwrite(arrow_table)
elif write_mode == "append":
    table.append(arrow_table)
```

Note: `pyarrow` is imported at the module level (Sub-step 2), not inline.
Use `{target.catalog}` from the config for the catalog name -- do not
hardcode `"glue_catalog"`.

Log the target table name and write completion.

### Sub-step 11: Reconciliation

For Lambda, generate a synchronous call to the reconciliation Lambda
(`InvocationType="RequestResponse"`):

```python
lambda_client = boto3.client("lambda")
response = lambda_client.invoke(
    FunctionName=f"adp-{product_name}-recon-{env}",
    InvocationType="RequestResponse",
    Payload=json.dumps({"correlation_id": correlation_id})
)

# Read the payload once (StreamingBody can only be read once)
payload_bytes = response["Payload"].read().decode("utf-8")

# Check for Lambda invocation errors
if response.get("FunctionError"):
    logger.error(f"Reconciliation Lambda invocation failed: {payload_bytes}")
    return {
        "statusCode": 500,
        "body": json.dumps({
            "status": "FAILED",
            "error": "Reconciliation Lambda invocation failed.",
            "correlation_id": correlation_id
        })
    }

recon_result = json.loads(payload_bytes)
logger.debug(f"Reconciliation detail: {json.dumps(recon_result)}")

if recon_result.get("overall_status") != "PASS":
    logger.error("Reconciliation failed. See DEBUG log for detail.")
    return {
        "statusCode": 500,
        "body": json.dumps({
            "status": "FAILED",
            "error": "Reconciliation check failed.",
            "correlation_id": correlation_id
        })
    }
logger.info("Reconciliation passed.")
```

Key points:
- Use an early `return` for reconciliation failure, not `raise ValueError`.
  This is consistent with the "do not re-raise" Lambda pattern (error
  signaling via return values).
- Check `response.get("FunctionError")` before reading the payload to detect
  Lambda invocation errors (throttling, timeout, etc.).
- The `Payload.read()` returns `bytes` -- decode with `.decode("utf-8")`.
- Log the full recon payload at DEBUG level only (not ERROR) to avoid leaking
  sensitive schema/row-count details.

If `reconciliation.rules` is empty or absent, log a warning and skip.

## Cross-Cutting Concerns

1. **Structured logging**: Correlation ID per invocation via `logging.LoggerAdapter`.
   Formatter: `%(asctime)s | %(levelname)s | %(correlation_id)s | %(message)s`.

2. **Error handling**: Top-level try/except in handler. Return structured
   JSON response with statusCode 200 (success) or 500 (failure).
   Do NOT re-raise -- Lambda uses return values for error signaling.
   Reconciliation failures inside the `try` block use early `return` with
   a 500 response, not `raise`. Do NOT include `str(e)` in the response
   body -- use a generic error message and rely on `correlation_id` to
   correlate back to CloudWatch logs.

3. **Reconciliation**: Synchronously invoke the reconciliation Lambda
   (`adp-{product.name}-recon-{env}`) using `InvocationType="RequestResponse"`.
   Check `response.get("FunctionError")` before reading the payload. Check
   `overall_status` in the response and return a 500 response if not `"PASS"`.

4. **Connection safety**: Use context managers (`with ... as conn:`) for
   Snowflake connections to ensure cleanup on exceptions. Pass `database`
   and `schema` as `connect()` parameters rather than using `USE DATABASE`
   / `USE SCHEMA` statements.

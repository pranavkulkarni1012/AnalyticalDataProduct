# Skill: run-tests

## Description

Executes the pytest suite for a product. Resolves the test directory from the
config (`pipelines/{product.name}/tests/`), runs pytest with JUnit XML output and
optional coverage measurement, and returns a structured summary the caller (the
`test-agent` or `/test-pipeline`) can use to drive reporting.

The generated test suite makes **real connections** to Snowflake (read-only
OAuth) and AWS (Secrets Manager, Glue catalog, Step Functions). This skill
sets `ENV` and AWS region on the subprocess environment and invokes pytest;
the suite handles all live connection logic (skipping tests when a service
is unreachable rather than failing).

## Inputs

`$ARGUMENTS` may contain:
- A config path (e.g., `configs/monthly_revenue.yaml`) -- resolves to
  `pipelines/{product.name}/tests/`. If omitted, scan `configs/*.yaml` (single
  config rule applies).
- `--run-id <uuid>` -- write JUnit XML to `artifacts/test/{run_id}/junit-results.xml`.
  If omitted, generate a UUID and surface it in the output.
- `--coverage` -- enable `pytest-cov` and write `coverage.xml` next to JUnit.
- `--categories <comma-list>` -- maps category names to pytest selection rules:
  - `config` -> `test_config_integrity.py`
  - `sql` -> `test_sql_query.py`
  - `source` -> `test_source_connection.py`
  - `target` -> `test_iceberg_target.py`
  - `recon` -> `test_reconciliation_rules.py`
  - `dq` -> `test_data_quality_rules.py`
  - `parameters` -> `test_parameter_substitution.py`
  - `smoke` -> `-m smoke`
  - `integration` -> `-m integration`
  - `step_function` -> `test_step_function_asl.py`
  - `recon_module` -> `test_recon_module.py`
  - `negative` -> `-m negative`
  Multiple categories OR together (pytest receives both file lists and `-m` expressions).
- `--no-fail-on-error` -- always exit 0 from this skill regardless of pytest
  exit code. Default behavior: exit 0 on test failures (1, 2, 5) -- those are
  reportable outcomes -- and exit non-zero only on harness errors (3, 4 = bad usage,
  internal error).

## Output

1. JUnit XML: `artifacts/test/{run_id}/junit-results.xml`
2. Coverage XML (if `--coverage`): `artifacts/test/{run_id}/coverage.xml`
3. Console summary (printed by pytest + a final structured block from this skill)
4. Skill-level result JSON written to `artifacts/test/{run_id}/run-summary.json`:
   ```json
   {
     "run_id": "...",
     "config_path": "...",
     "product_name": "...",
     "tests_dir": "...",
     "command": "pytest ... (exact argv)",
     "exit_code": 0,
     "duration_seconds": 12.34,
     "totals": {"total": 87, "passed": 84, "failed": 2, "skipped": 1, "errors": 0},
     "categories_requested": ["config", "sql"],
     "junit_xml": "artifacts/test/{run_id}/junit-results.xml",
     "coverage_xml": "artifacts/test/{run_id}/coverage.xml"
   }
   ```

## Steps

### Step 1: Resolve Inputs

1. Parse `$ARGUMENTS` and extract config path, `--run-id`, `--coverage`,
   `--categories`, `--no-fail-on-error`.
2. Resolve `product.name` and `compute.engine` by reading the config:
   ```bash
   python3 -c "
   import yaml, sys
   c = yaml.safe_load(open(sys.argv[1]))
   print(c['product']['name'], c['compute']['engine'])
   " "$config_path"
   ```
3. Compute `tests_dir = pipelines/{product.name}/tests`. If it does not exist,
   stop with: "No tests found at {tests_dir}. Run /generate-test-cases first."
4. If `run_id` was not provided, generate one with `python3 -c "import uuid;
   print(uuid.uuid4())"` and surface it in the output.
5. Create the artifacts directory:
   ```bash
   mkdir -p artifacts/test/{run_id}
   ```

### Step 2: Build the pytest Command

Base argv:
```
pytest {tests_dir}
  --rootdir pipelines/{product.name}
  -c pipelines/{product.name}/pytest.ini
  -ra
  --junitxml=artifacts/test/{run_id}/junit-results.xml
  --tb=short
```

**Environment variables** are exported on the pytest subprocess so the live
fixtures pick the correct target:

- `ENV` -- from `--env` flag (default `dev`). The conftest reads this and
  refuses integration tests against `prod` unless `LIVE_TESTS_AGAINST_PROD=1`
  is also set.
- `AWS_REGION` -- inherited from the parent shell, defaults to `us-east-1`.
- `AWS_PROFILE` -- inherited from the parent shell.
- `HTTP_PROXY` / `HTTPS_PROXY` -- set by the conftest from the config's
  `source.connection.proxy` block before opening Snowflake connections; do
  not pre-set them here.

If `--coverage`:
```
  --cov=pipelines/generic/{engine}
  --cov-report=xml:artifacts/test/{run_id}/coverage.xml
  --cov-report=term-missing
```

If `--categories` is specified, build the selector(s):
- For each "file" category, append `tests_dir/test_<file>.py`
- For each "marker" category, append `-m <marker>` (combine multiple markers
  with `or`, e.g. `-m "smoke or negative"`)
- File and marker selectors can be combined; pytest unions the selections.

If a requested category's file or marker yields **no collected tests** (pytest
exits with code 5), treat it as a non-fatal warning -- log it and continue.

### Step 3: Pre-flight Tool Checks

Verify pytest is installed:
```bash
python3 -m pytest --version || { echo "pytest not installed. pip install -r requirements.txt"; exit 1; }
```

If `--coverage`, also verify `pytest-cov`:
```bash
python3 -c "import pytest_cov" || { echo "pytest-cov not installed. pip install pytest-cov"; exit 1; }
```

If either is missing, write an error result to `run-summary.json` with
`exit_code: 127` and stop.

### Step 4: Execute

Run the assembled pytest command via `Bash`. Capture stdout, stderr, and the
exit code. Wall-clock the duration with `time` or by recording `time.time()`
before/after.

**Exit code interpretation (pytest convention):**

| Code | Meaning | Skill Behavior |
|------|---------|---------------|
| 0 | All tests passed | success |
| 1 | Tests were collected and run, some failed | success (failures are reportable) |
| 2 | Test execution interrupted by user | propagate (something is wrong) |
| 3 | Internal pytest error | propagate (harness broken) |
| 4 | pytest command-line usage error | propagate (skill bug) |
| 5 | No tests collected | warning, success |

`--no-fail-on-error` forces success regardless. Default behavior maps codes 0/1/5
to skill exit 0 and codes 2/3/4 to skill exit 1.

### Step 5: Parse Totals from JUnit XML

After pytest completes, parse the JUnit XML to extract totals:

```bash
python3 -c "
import xml.etree.ElementTree as ET, json, sys
root = ET.parse(sys.argv[1]).getroot()
# JUnit root may be <testsuites> with one or more <testsuite>, or a single <testsuite>.
suites = root.findall('testsuite') if root.tag == 'testsuites' else [root]
total = sum(int(s.get('tests', 0)) for s in suites)
failed = sum(int(s.get('failures', 0)) for s in suites)
errors = sum(int(s.get('errors', 0)) for s in suites)
skipped = sum(int(s.get('skipped', 0)) for s in suites)
passed = total - failed - errors - skipped
print(json.dumps({'total': total, 'passed': passed, 'failed': failed, 'skipped': skipped, 'errors': errors}))
" "artifacts/test/{run_id}/junit-results.xml"
```

If the JUnit XML does not exist (pytest crashed before writing it), record
zeros and an `error_message` in the summary.

### Step 6: Write `run-summary.json`

Compose the JSON described under Output and write it to
`artifacts/test/{run_id}/run-summary.json`.

### Step 7: Console Summary

Print a compact block:

```
========================================
PYTEST RUN COMPLETE
Run ID:    {run_id}
Product:   {product_name}
Engine:    {engine}
Tests dir: {tests_dir}
========================================

Command:
  pytest {tests_dir} ... (exact argv)

Result:    PASS | FAIL | NO_TESTS | ERROR
Exit code: {code}
Duration:  {seconds}s

Totals:
  Total:   {total}
  Passed:  {passed}
  Failed:  {failed}
  Skipped: {skipped}
  Errors:  {errors}

Artifacts:
  - artifacts/test/{run_id}/junit-results.xml
  - artifacts/test/{run_id}/coverage.xml          (if --coverage)
  - artifacts/test/{run_id}/run-summary.json

Next:
  - /generate-test-report --run-id {run_id}
========================================
```

## Error Handling

| Failure | Action |
|---------|--------|
| Tests directory missing | Stop. Tell the user to run `/generate-test-cases`. |
| pytest binary missing | Write `run-summary.json` with `exit_code: 127`, stop. |
| Coverage requested but `pytest-cov` missing | Same as above (127). |
| pytest exits 2/3/4 (harness error, not test failure) | Capture stderr in `run-summary.json` and exit non-zero. |
| pytest exits 5 (no tests collected for the requested categories) | Treat as warning, exit 0, record zero totals. |
| JUnit XML missing after run | Record an `error_message` in summary, exit non-zero unless `--no-fail-on-error`. |
| Test failures (exit 1) | Exit 0 -- failures are reportable, not skill errors. |

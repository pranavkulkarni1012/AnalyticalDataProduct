Claude Feature Map

CLAUDE.md Persistent Instructions

Two levels: Global (org-wide constraints: Snowflake read-only, naming conventions, proxy rules) and Repo-level (product-specific context, domain rules, available skills).

Skills Reusable Capabilities

5 core skills in .claude/skills/, each as a SKILL.md with YAML frontmatter: /generate-pipeline, /validate-config, /generate-terraform, /generate-step-function, /run-recon. Invoked as slash commands.

Subagents Specialized Agents

6 agents defined in .claude/agents/<name>/AGENT.md, each with a single responsibility: Requirement Parser, Spec Generator, Config Generator, Pipeline Generator, Infra Agent, QA Agent. Auto-discovered by Claude Code.

Hooks Automated Guardrails

4 hooks using PreToolUse, PostToolUse, and Stop events in .claude/settings.json: config validation, code lint, Terraform plan check, post-deploy recon. Hooks receive JSON on stdin and return exit code 2 to block unsafe operations (exit 0 = allow).

MCP Servers External Integrations (JIRA + Confluence Only)

Configured in .mcp.json (project root). Single atlassian MCP provides both JIRA and Confluence tools. JIRA: Fetch tickets, add comments, transition status. Confluence: Create/update spec pages, publish runbooks. No other MCP servers allowed.

Config-Driven Framework

A single YAML configuration file is the source of truth for every data product.

Sources

Snowflake tables with OAuth + proxy config, column selection, filters

Transformations

Joins (inner/left/right/full), aggregations (sum/count/avg), column mappings, custom SQL

Target

Iceberg table via Glue Catalog, S3 path, write mode, partition spec, sort order

Reconciliation

Row count, sum, distinct count, null checks with configurable tolerance %

Data Quality

Not-null, uniqueness, range, regex, custom checks per column

Runtime

Glue 4.0, worker type/count, timeout, Spark configs, tags

Code Generation: Template + Skill Approach

Template Library

templates/
  glue_job_boilerplate.py — Spark/Glue init, logging, error handling

  iceberg_writer.py    — Glue Catalog write, partitioning
  reconciliation.py   — Source vs target comparison checks

How It Works

  1. Skill reads the config YAML
  2. Templates are composed based on config structure
  3. Claude fills in business logic (joins, aggs, filters)
  4. Output: complete, runnable PySpark job

Snowflake Connection Pattern

# 1. Set proxy env vars
os.environ["http_proxy"] = proxy_url
os.environ["https_proxy"] = proxy_url

# 2. Fetch OAuth token from Secrets Manager
secret = secretsmanager.get_secret_value(
  SecretId="adp/snowflake/.../oauth"
)
token = json.loads(secret)["access_token"]

# 3. Read via Spark Snowflake connector
df = spark.read \
  .format("net.snowflake.spark.snowflake") \
  .options(authenticator="oauth",
           token=token,
           use_proxy="true") \
  .load()

Snowflake is READ-ONLY. CLAUDE.md + hooks enforce this at every stage.

Bootstrap Flow

  1. Clone template repo
  2. Update CLAUDE.md with product context
  3. Create config YAML (or let Claude generate from Jira ticket)
  4. Run Claude: it generates all code, infra, tests
  5. Push to Git → CI/CD takes over
